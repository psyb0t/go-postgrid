# go-postgrid

Unofficial Go client for the PostGrid print and mail API, including address verification, generated from the OpenAPI document PostGrid publishes. If you only want to use the client from an agent, read [.agents/skills/go-postgrid/SKILL.md](.agents/skills/go-postgrid/SKILL.md) instead; this file is about changing the code.

## Architecture

One generated package, `postgrid`, at the module root, driven by `gen.go`:

`scripts/fetch-spec.sh` downloads `https://raw.githubusercontent.com/postgrid/postgrid-node/main/.stats.yml`, reads its `openapi_spec_url` and downloads the Stainless-hosted document to `api/openapi.yaml` → `scripts/patch-spec.sh` writes `api/openapi.patched.yaml` → oapi-codegen with `config.yaml` → `client.gen.go`.

The upstream document is titled PostGrid Address Verification API, version 1.0, but also contains the print and mail operations. It uses OpenAPI 3.0.0 and needs a patch to collapse duplicate identical `anyOf` references in the letter, postcard, self mailer and snap pack creation responses.

The patch also names the inline text branch of the shared search parameter to prevent undefined `N0` references in generated methods. Both text and structured search remain supported.

## Stack

- Go 1.26.10.
- oapi-codegen, pinned as a `tool` dependency in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime`.

## Layout

- `gen.go`, `config.yaml`, `client.gen.go`: the package.
- `client_test.go`, `example_test.go`: tests, including the README example.
- `scripts/`: spec download, YAML patch wrapper, lint and security scan scripts.
- `internal/cmd/patch-spec/`: YAML patch tool invoked through `go tool`.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- The Stainless spec URL includes a content hash. Discover it from the SDK metadata instead of hardcoding the current URL.
- Both security schemes use `X-API-Key`. Print and mail and address verification use their respective API keys; test and live print/mail data depend on the key.
- Without the `number` to `float64` mapping in `config.yaml`, unformatted numbers become `float32`.
- Method names follow operation IDs. For example, `Contacts_list` becomes `ContactsListWithResponse`. Combined JSON and multipart operation IDs produce longer names; inspect the generated methods before using them.
- Mail creation with a live key can send physical mail and incur charges. Tests use local HTTP servers only.
- `make generate` always downloads the current spec, so it can change the client even when nothing here changed. Review the generated diff before committing it.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
